## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Was zu evaluieren ist

In authService.ts existiert die Funktion assignRoleToUser(userId, roleName), die AppDataSource.getRepository(UserRole) aufruft. UserRole wird aber nirgends importiert und existiert nicht als Entity. Die Funktion wird in register/+page.server.ts importiert, aber NIE aufgerufen.

## Ist-Zustand (belegt)
- User.role ist ein direkter ManyToOne auf Role (User.ts:50-52), KEIN m:n.
- role-User-Verbindung läuft also direkt, nicht über eine UserRole-Junction.
- registerUser() (authService) setzt die Rolle bereits korrekt im User-Objekt (register/+page.server.ts:21 übergibt role mit).
- Es gibt KEINE UserRole-Entity in entities/.
- Die einzigen UserRole-Treffer sind die defekte Funktion + ein Kommentar "via UserRole (idempotent)".

## Die offenen Fragen (nur du kannst sie beantworten)
1. War "UserRole" mal als eigenständige m:n-Junction-Tabelle gedacht (d.h. ein User kann mehrere Rollen haben) und wurdest du auf das einfachere User.role-ManyToOne-Modell gewechselt? Oder ist UserRole nur ein vergessener Reliktname?
2. Brauchst du mehrere Rollen pro User (dann müsste UserRole nachgerüstet werden) oder reicht eine Rolle pro User (dann ist assignRoleToUser toter Code und kann weg)?
3. Soll assignRoleToUser (falls m:n gewünscht) korrekt auf Basis des bestehenden SubRole-Modells (UserSubRole) neu gebaut werden, oder ist das ein anderes Konzept?

## Empfehlung (vorab, zur Orientierung)
Der Code ist funktional nicht kaputt (die defekte Funktion wird nie aufgerufen), aber er ist technische Schuld: eine Funktion, die eine Phantom-Entity referenziert. Mein Vorschlag: assignRoleToUser + den ungenutzten Import entfernen, da registerUser die Rolle bereits sauber setzt. Falls du stattdessen m:n-Rollen willst, wäre das ein neues Feature (UserRole-Entity), kein Fix.
